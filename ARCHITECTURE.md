## 1. Overview & Goals

### 1.1 Project Purpose

**Projects Oversight (P.O.A. Registry)** is a geospatial integrity platform for transparent public infrastructure auditing. It enables citizens and officials to submit on-site photographic evidence of project progress, which is automatically verified against registered project coordinates using EXIF metadata analysis and computer vision.

### 1.2 Core Objectives (Inferred from Code)

| Objective | Evidence |
|-----------|----------|
| **Anti-fraud geospatial verification** | `detector.py:verify_photo_location()` — rejects photos whose GPS EXIF data falls outside a 200m radius of the registered project coordinates |
| **Computer vision contextual validation** | `detector.py:analyze_image_objects()` — uses YOLOv8 to confirm workforce presence ("person") or delivery assets ("truck", "car") match the audit type |
| **Privacy-preserving evidence handling** | `privacy_shield.py:blur_sensitive_data()` — automatically redacts faces, bodies, and vehicle license plates before storage |
| **Offline-first mobile data capture** | Frontend `offlineDb.js` + `syncManager.js` — IndexedDB write-ahead logging with background sync when connectivity returns |
| **Public accountability map** | `routers/maps.py` + `ProjectMap.jsx` — GeoJSON FeatureCollection visualization of registered projects |
| **Audit trail immutability** | `main.py:log_verification_result()` — every verification writes to `audit_logs` table with timestamp, status, and distance metrics |

### 1.3 Target Users

- **Field auditors / citizens** — Capture and submit geotagged photos via mobile browser
- **Project administrators** — Register projects, review audit logs
- **Public / oversight bodies** — View map of projects and verification statuses

**Purpose**: Bootstraps the API, configures CORS, mounts routers, defines all REST endpoints, and manages DB connections.

- `privacy_shield.py`: `blur_sensitive_data`

**External Dependencies**:
- PostgreSQL (credentials via environment variables: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`)
- File system (temp file staging in CWD)
- YOLOv8 model file (`yolov8n.pt` in CWD)

- **DB**: Reads `projects`, `contractors`, writes `audit_logs`
- **FS**: Creates `temp_{idx}_{filename}` during processing, deletes in `finally` block
- **Network**: None directly (delegates to `utils.py` for Nominatim)

**State Mutations**:
- None in-process (stateless request handling)
- DB commits via `log_verification_result()`

**Error Handling**:
- `HTTPException(500)` for DB errors
- `HTTPException(404)` for missing project
- Per-file try/catch in `/api/verify` loop — individual failures don't abort batch
- Returns structured error in response body: `{status: "REJECTED", reason: "PROCESSING_ERROR", detail: "..."}`

**Notable Patterns**:
- **Hardcoded secrets** — DB password in source (critical security finding)
- **Blocking DB driver** — `psycopg2` used in async FastAPI routes (blocks event loop)
- **Temp file collision risk** — `temp_{idx}_{filename}` uses index only; concurrent requests could collide
- **No request validation** — Raw `Form`/`File` parameters, no Pydantic models

#### 4.1.2 `detector.py` — Geospatial Verification & Computer Vision Engine

**Purpose**: Core verification logic — EXIF GPS extraction, proximity checking (point-radius + polygon), YOLOv8 object detection.

**Public Interface**:

| Function | Signature | Returns |
|----------|-----------|---------|
| `get_project_coordinates` | `(project_id: int) -> (float, float, str) \| None` | `(lat, lng, project_name)` |
| `get_exif_gps` | `(image_path: str) -> (float, float) \| None` | Decimal degrees `(lat, lng)` |
| `verify_photo_location` | `(project_lat, project_lng, photo_path, max_radius_meters=200) -> dict` | Status dict |
| `verify_polygon_boundary` | `(citizen_lat, citizen_lon, boundary_coords) -> dict` | Status dict with variance |
| `analyze_image_objects` | `(image_path: str, log_type: str) -> dict` | `{status, detected_objects[], message}` |

**Verification Status Values**:
- `"VERIFIED"` — Within radius / inside polygon
- `"REJECTED"` — No GPS metadata OR outside radius
- `"VARIANCE_OBSERVED"` — Outside polygon, distance returned
- `"FLAGGED"` — CV context mismatch (e.g., workforce log but no person detected)
- `"PASSED"` — CV context match
- `"SKIPPED"` — Ultralytics not installed
- `"ERROR"` — Exception during processing

**Internal Logic Details**:

**EXIF Parsing** (`get_exif_gps`):
- Uses `exifread.process_file()` on binary file handle
- Reads `GPS GPSLatitude`, `GPS GPSLongitude`, `GPS GPSLatitudeRef`, `GPS GPSLongitudeRef`
- Converts DMS (degrees/minutes/seconds) to decimal with rational number handling
- Applies sign based on reference (S/W = negative)

**Point-Radius Verification** (`verify_photo_location`):
- Computes geodesic distance via `geopy.distance.geodesic` (WGS84)
- Default `max_radius_meters=200`
- Returns `distance_meters` rounded to 2 decimals

**Polygon Verification** (`verify_polygon_boundary`):
- Expects `boundary_coordinates` as `[(lat, lng), ...]` (min 3 points)
- Creates `shapely.geometry.Polygon` (note: swaps to `[lng, lat]` for Shapely's x,y order)
- Uses `Point.within()` / `touches()` for inclusion test
- If outside, computes nearest point on polygon boundary via `shapely.ops.nearest_points`
- Returns geodesic distance to nearest boundary point

**Computer Vision** (`analyze_image_objects`):
- Lazy-loads `YOLO("yolov8n.pt")` on first call (model cached in memory)
- Runs inference: `model(image_path)`
- Extracts class names from `r.boxes.cls` → `model.names[int(c)]`
- **Context rules**:
  - `log_type == "workforce"` → requires `"person"` in detections
  - `log_type == "delivery"` → requires any of `["truck", "car", "bench"]`
  - `log_type == "public_project"` → no specific requirement (always `PASSED` if model loads)

**Dependencies**:
- External: `ultralytics`, `exifread`, `geopy`, `shapely`, `psycopg2`
- Model file: `yolov8n.pt` (must exist in CWD)

**Error Handling**:
- DB errors → `print` + return `None`
- Missing EXIF → structured `REJECTED` dict
- CV errors → `ERROR` dict with exception message
- All errors logged via `print()` (no structured logging)

#### 4.1.3 `privacy_shield.py` — PII Redaction (GDPR/Privacy Compliance)

**Purpose**: Detect and blur faces, bodies, and vehicle license plates in submitted photos before any storage/transmission.

**Public Interface**:

| Function | Signature | Returns |
|----------|-----------|---------|
| `blur_sensitive_data` | `(image_path: str) -> bool` | `True` if processed, `False` on error |

**Detection Classes** (COCO IDs):
| Class ID | Label | Target |
|----------|-------|--------|
| 0 | person | Faces, bodies |
| 2 | car | License plates |
| 3 | motorcycle | License plates |
| 5 | bus | License plates |
| 7 | truck | License plates |

**Algorithm**:
1. Load image via `cv2.imread()`
2. Run `model(img, verbose=False)` — YOLOv8 nano
3. For each detection with `confidence > 0.25` and class in target list:
   - Clamp bounding box to image bounds
   - Extract ROI: `img[y1:y2, x1:x2]`
   - Apply `cv2.GaussianBlur(roi, (99, 99), 0)` — heavy 99×99 kernel
   - Write back: `img[y1:y2, x1:x2] = blurred_roi`
4. If any blurring occurred, overwrite original file via `cv2.imwrite()`

**Side Effects**:
- **Mutates the input file in place** — caller must copy if original needed
- Loads YOLO model at module import time (global `model = YOLO("yolov8n.pt")`)

**Error Handling**:
- Catches all exceptions, prints error, returns `False`
- No re-raise — silent failure mode (caller in `main.py` ignores return value)

**Critical Finding**: The blurring happens **after** CV verification in `main.py` (line 225→228), but the verification uses the **original unblurred image**. This is correct for detection accuracy but means the stored temp file gets blurred before cleanup. No blurred copy is preserved or returned to frontend.

#### 4.1.4 `utils.py` — Cross-Cutting Utilities

**Purpose**: Anonymous session tracking + admin coordinate verification against OpenStreetMap.

**Public Interface**:

| Function | Signature | Description |
|----------|-----------|-------------|
| `generate_anonymous_tracker` | `(seed_data: str = None) -> str` | SHA-256 hex (16 chars) of UUID or seed |
| `verify_admin_coordinates` | `(lat: float, lon: float, expected_county: str) -> bool` | Reverse geocodes via Nominatim, checks county match |

**`generate_anonymous_tracker`**:
- Uses `uuid.uuid4()` if no seed provided
- Returns first 16 chars of SHA-256 (64 bits entropy)
- Used in `main.py` for `anonymous_session_signature` in API response

**`verify_admin_coordinates`**:
- Calls `https://nominatim.openstreetmap.org/reverse?lat={lat}&lon={lon}&format=json`
- User-Agent: `"POA_Registry_Admin_Input_Audit_Engine"`
- 5-second timeout
- Extracts `address.county` or `address.region`
- Case-insensitive substring match against `expected_county`
- **Fail-open design**: On network error or non-200, returns `True` (allows insertion to proceed)

**Dependencies**:
- `requests` (blocking HTTP)
- `logging` (configured but only used in this module)

**Notable**: This is the **only** module using Python `logging`; rest use `print()`.

#### 4.2.2 `TelemetryForm.jsx` — Photo Capture & Verification Form

**Purpose**: Handles the complete capture → verify → submit flow with permission gating.

**Props** (from `App.jsx`):
```jsx
{
  selectedProject,           // { id, project_name, target_lat, target_lng, ... }
  setOfflineCount,           // Callback to update header badge
  setLoading,                // Global loading state
  setErrorMsg,               // Global error display
  setScanResult              // Global results display
}
```

**Internal State**:
- `logType` — `'public_project' | 'workforce' | 'delivery'`
- `selectedFile` — File object from camera input
- `isCalibrating` / `calibratedCoords` — GPS acquisition UI state
- `showPermissionModal` — Custom consent dialog (pre-browser prompt)

**Flow**:
1. User clicks "Snap Project Photo" → `handlePhotoClick()`
2. Shows `ConsentCard`-style modal (`showPermissionModal`)
3. On "Allow" → `navigator.geolocation.getCurrentPosition({enableHighAccuracy: true, timeout: 12000})`
4. On GPS success → programmatically clicks hidden `<input type="file" capture="environment" accept="image/*">`
5. User takes photo → `onChange` sets `selectedFile`, shows preview
6. User clicks "Execute Audit Check" → `handleVerifySubmit()`
7. **Stages to IndexedDB** (write-ahead):
   - Generates `transactionId`, `payloadHash` (via `crypto.js`)
   - Stores blob + metadata with `status: 'pending'`
   - Increments `offlineCount`
8. **Posts to API** (`axios.post('/api/verify', formData, {headers: {'X-Idempotency-Key': transactionId}})`)
9. On success → `removeRecordLocally()`, decrement badge, show `scanResult`
10. On failure → record stays `pending`, error shown, user can retry or wait for background sync

**Notable**: Duplicates significant logic from `App.jsx` (`handleVerifySubmit` in both). `App.jsx` version is more complete (includes AI audit display); `TelemetryForm.jsx` is the active one used in render.

```

    │   ├─ detector.analyze_image_objects(temp_path, log_type)

    │   │   └─ INSERT INTO audit_logs ...
    │   └─ Delete temp file
    │
    ▼
Response: { summary, results[] }
    │
    ▼
Frontend
    │
    ├─ On 200: removeRecordLocally(transactionId), update badge, show results
    └─ On error: keep in IndexedDB, show error, auto-retry via syncManager
```
